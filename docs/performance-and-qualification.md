# Performance and release qualification protocol

**Status:** proposed gates and test design, not measured performance or proof that any game executable exists. Decision baseline 2026-10-07. Implementation ownership: [P01–P06 and R01–R06](superpowers/plans/05-performance-release.md); architecture and simulation authority: [architecture](architecture.md). No launch platform is qualified merely because Unreal supports it. All commands below are **future implementation checks, not currently executable**.

## Early proof and capacity decision

Before funding production-quality flagship art, build the small First Shipment facility end-to-end, run its complete fun/playtest gate and benchmark a *generated representative* flagship load with temporary original/licensed geometry. Profile the real cooked renderer and domain worker on target hardware; estimate the geometry, texture, shadow, visibility and simulation costs independently. If a target fails, preserve fidelity and report the miss; reduce legitimately reducible presentation cost, change authored density or revise scope/budget with an explicit decision. Never report a deferred solver, invisible failures, reduced crop integration or distant-worker teleportation as an optimization. Required resources are access to licensed Unreal 5.8.3 and platform SDKs, three reproducible test machines and drivers, managed macOS signing access, trusted build runners, rights-cleared sample models, storage for private cooked artifacts and traces, and human QA/playtest/rights review. These are needs, not funded positions or a delivery schedule.

## Target matrix, not guarantees

| Tier / reference system | Render setting | Sustained frame gate | Working set target |
|---|---|---|---|
| Baseline Windows 11 x64, Ryzen 5 7600, RTX 4060 8 GiB, 32 GiB RAM | 1920×1080 output and internal, baseline raster/conventional LOD | 60 fps; p95 frame <=16.7 ms, p99 <=25 ms | game peak resident/working <=10 GiB; measured GPU dedicated use <=7 GiB |
| Baseline Ubuntu 24.04 x64 on equivalent CPU/GPU/RAM | 1920×1080 output and internal, qualified Vulkan baseline | same 60 fps / p95/p99 | same game and GPU limits |
| High Windows 11 x64, Ryzen 7 7800X3D, RTX 4080 16 GiB, 32 GiB RAM | 3840×2160 output, TSR 2560×1440 internal, high settings | 60 fps; p95 <=16.7 ms, p99 <=25 ms | GPU dedicated <=12 GiB; log system use |
| Mac macOS 15+ Apple Silicon M2 Pro 16 GiB | 1920×1080 output/internal, medium raster + conventional LOD; no HWRT/Nanite requirement | 30 fps; p95 <=33.3 ms, p99 <=50 ms | game-attributable unified memory <=10 GiB |

A Mac M2 Pro is a separate native ARM64 build, cook, signature and physical-device qualification, not an x64 claim or emulation result. Ubuntu 22.04 may be qualified additionally per platform requirements, but Ubuntu 24.04 is the reference measurement. Linux renderer/API and Mac Metal are logged. HDR is optional and cannot gate SDR baseline or require a mandatory vendor upscaler/plugin. 4K-native is measured and reported separately without a 60-fps promise; 4K UI renders at output resolution even when TSR uses 1440p internally. Report UE quality scalars, screen percentage, foliage/shadow/reflection tiers, RHI, upscaler and whether dynamic resolution was disabled. No vendor-only interpolation/frame generation may count toward frame gates.

## Immutable workloads and evidence

P01 generates `benchmarks/fixtures/first-shipment/`, `benchmarks/fixtures/flagship-stress/` and `benchmarks/routes/` from rights-cleared recipes. Every fixture is immutable after sealing; a new recipe/model/toolchain creates a new digest. Store manifest SHA-256 for the canonical byte sequence of **all** workload inputs (scenario program, semantic/render pack manifests and digests, model pack, weather/fault/job schedule, seed, route and camera keys), and report each file SHA-256 alongside the aggregate workload SHA-256. Do not invent a digest before generating the files; missing hashes invalidate the result. Use fixed model-pack version and seed `17032026` for the reference workload; log the exact compiler/engine commits and cooked-content digest. Asset licenses restrict publishing raw fixtures or screenshots. Store private capture metadata and approved/redacted samples separately.

Generated flagship stress contains **256 climate zones, 16,000 equipment instances, 20,000 cohorts, 1,000 logical workers and 1,000,000 representative plant instances in total** (not one million Actors nor simultaneously visible specimens), with at most 64 detailed nearby workers. Distribution includes stacked storeys, greenhouse glazing, dense rack aisles, mechanical equipment, inventory/travel bottlenecks, active failures, maintenance jobs, energy/water shortages, harvesting, orders and wages. Generator must assert exact counts, referential integrity, valid route/capacity topology and that plant cohorts account for every representative instance; admission failures are test failures, not truncated populations. Maintain a separate First Shipment facility and a loaded small-facility save for player-fun and startup measurement; a generated stress fixture cannot replace a played scenario.

Canonical camera/interaction route `benchmarks/routes/facility-tour.json` is time-indexed with explicit timestamps and named transforms: cold launch -> load saved lobby -> enter production aisle -> pass rolling benches under lamps -> inspect close leaf/fixture and operate toggle -> cross glazing to greenhouse -> view long aisle with moving carts/64 detailed nearby workers -> inspect mechanical room -> overhead design view -> return first person -> dispatch bay -> save/exit/relaunch/resume. Log camera transform, field of view, player actions and internal/output resolutions at each marker. Record an uncontrolled interactive pass separately; scripted reproducibility never substitutes for real play. Capture comparator frames at `close-leaf`, `bench-clearance`, `glazing`, `mechanical-ports`, `overhead-utilities` and `dispatch`. An attract-mode or screensaver flythrough must follow this same loaded-facility route and retain operational overlays on demand; qualifying an empty menu/flyover is invalid.

The route must additionally alternate first-person/third-person beside benches/doorways, while carrying a tray and in every shipping vehicle's operator/chase view. Record view state and collision-adjusted camera distance/FOV, then enter overhead and return to the prior view. Verify domain state/work/load continuity and separate saved on-foot/vehicle preference. Measure both views; the wider third-person visible workload is not exempt from frame/memory targets.

For each evidence record include build+source+fixture/pack hashes, engine/OS/kernel/GPU/driver/API, monitor mode, power/thermal mode, storage, CPU/RAM/VRAM, launch state, display/window/renderer/quality settings, game clock speed, route camera/seed and start/end UTC. Use an otherwise idle reference machine, a fresh process per run, locked clocks or logged variation and three valid repetitions. Store raw timestamped frame intervals, Unreal Insights CPU/GPU/IO traces and memory samples plus computed percentiles and screenshots privately, not only an aggregate score. Profile editor separately; only native packaged development and release builds count for release performance. Where measurement tools differ by platform, record each metric's source and known exclusions.

## Definitions and gates

- **Frame intervals:** present-to-present wall-clock interval for every rendered gameplay frame during route from first usable loaded view, excluding only explicitly labeled setup/loading intervals; no pause, menu, dropped/cancelled frame or speed-change interval is silently filtered. Percentiles are nearest-rank over each run's sorted intervals, p95 = element ceil(.95N), p99 = element ceil(.99N); fps = actual presented frame count / elapsed sampling seconds, not 1000 divided by average render-thread time. Require the per-run frame gates above for all three repetitions and include average, median, maximum and p99 separately. p99 is not a substitute for reporting single long hitches.
- **Hitches:** count contiguous present gaps >50 ms and report duration, frame marker, CPU/GPU/loading attribution. Proposed startup/PSO gate: after first usable view, **zero gaps >100 ms attributable to shader compilation or PSO creation** on cold and warm routes; other >100 ms gaps require triage and are release blockers on baseline unless formally accepted in an explicit revised gate. Also report total >50 ms and p99. Cold means freshly installed cooked build with no application PSO/user shader cache, OS driver cache state documented rather than falsely called clean; warm means second launch same build/driver after route traversal. Log compilation counts and cache hit/miss, never prime the cold pass invisibly. Loading before usable view has its own stopwatch and visible progress; no unbounded black frame. Benchmark CPU game/render, GPU, streaming stalls and IO to separate causes.
- **Memory:** sample system resident/working game process and committed memory, GPU dedicated use where exposed and Mac game-attributable unified resident footprint every second, plus peak during load/tour/save, and separately report shared/system/driver reservations and trace overhead. Baseline working <=10 GiB, dedicated VRAM <=7 GiB, Mac unified <=10 GiB, high VRAM <=12 GiB are admission targets, not OS telemetry equivalences. Simulation core working memory <=512 MiB excluding save/trend archives; count core-owned arenas, state/indexes and queue buffers at peak, never omit domain objects by reclassifying them as renderer allocations. Memory-growth slope after warmup across campaign checkpoints must be bounded by documented retained history; repeated load/unload and save/reload return within 5% of same checkpoint baseline (proposed gate), with attribution for cache retention.
- **Acceleration:** on reference Windows/Linux, `flagship-stress` must run seven virtual days in <=420 wall seconds at requested 1440× with faults/jobs/production enabled and a co-running rendered view of that same world. Compare outcomes against the same fixed-step model run headlessly without wall-clock pacing, not a seven-real-day wait. Record achieved speed, frame percentiles, queue age, event totals and substeps. Separately capture the normal 1× presentation route. Apply S01–S08 numerical tolerances, never cross-architecture bit equality. Failure to reach speed is a failed target, not permission to drop events/increase integration steps. Mac gets measured acceleration but has no 1440× pass claim in this baseline.
- **Visual parity:** side-by-side golden views from approved source geometry and cooked build, same pose/FOV/light state, with annotated dimension lines and semantic IDs. Compare equipment envelope/pivot/ports, rolling-rail travel, service/aisle clearances and collision/access boundaries to source definition: positions/dimensions within 10 mm for fixed mechanical interfaces and within 25 mm for visible architectural alignment (proposed rendering/conversion tolerance, not real-world design certification); moving end-stops within 10 mm. LOD silhouettes may simplify leaves/remote racks but never shift a port, erase an obstruction or invent available aisle space. Independent reviewers inspect paired images and measured semantic overlays; perceptual differences in lighting are triaged, not fail solely on pixel hash. Color/HDR profiles have separate SDR references. Masking an error via camera mismatch fails.

## Persistence and long campaigns

P05 runs 30- and 90-virtual-day seeded campaigns with the same domain model: supply delays, failures, replacements, worker queues, contracts and construction changes. Take daily checkpoint signatures and verify stock/ledger conservation, unique dispatch receipts, failure alarm continuity, bounded solver residuals, no event loss, deterministic same-build replay, retained-window replay, checkpoint counts and memory growth. Run 100 repeated small-facility load/unload cycles and saves during ongoing worker advancement. Kill the process after writing snapshot, after journal flush and before/after manifest replacement using deterministic fault injection; restart must recover the last committed revision with prior manifest intact, or a typed missing/incompatible-content error. A missing optional branded render pack uses compatible licensed generic render only; a missing mandatory model pack never silently changes physics or resets a campaign. Migration creates a new save, preserves original, validates source/model rights, and exercises a rollback launch on the previous signed version. Qualified Windows replacement/flush and POSIX file+directory fsync paths must be tested on native filesystems, not assumed equivalent.

## Packaged platform and release acceptance

P06 runs the saved `first-shipment` route and `flagship-stress` on Windows, Linux and Mac from native packaged binaries, with keyboard/mouse, controller, rebindings, pause/resume, overhead view, first-person interaction, sound/subtitles and save/relaunch. Compare same-seed discrete command/event outcomes across systems and tolerance-defined numeric quantities; never promise ARM/x86 bit identity. Perform native startup, display-mode change, 1080p and high-resolution UI readability, input unplug/replug, and SDR screenshot review. Capture Mac separately with a valid native signature and no compulsory experimental rendering feature. Absent signed Mac package or physical Mac run means Mac gate fails. Report exact failing build/fixture, reproducible steps and severity; CI green without packaged visual/manual input passes cannot qualify release.

A security/release gate couples provenance with distribution: signed/approved rights manifests and private asset ingress, dependency lock + SBOM + third-party notices, untrusted mod boundary (strict schema, bounded decompression/counts/refs, no path escape, no native scripts or arbitrary URLs), no secrets on untrusted pull requests, trusted self-hosted licensed-engine runners, access-controlled artifact storage and retention. Reject malformed or revoked packs with a clear diagnostic and leave the current save untouched. Keep vendor source CAD and unapproved art out of public SDK, symbols and artifacts. Verify launcher/store install and offline start, signed Windows executable/installer and Mac Developer ID signing/notarization where channel requires it, Linux runtime library packaging and clean user-data paths, age-rating and rights/trademark review. English text remains localizable; controller-only complete first cycle, rebind conflict handling, subtitle coverage and color-independent alarms are release criteria. Release candidates require a played complete First Shipment cycle, age-appropriate content review, economy regression, scenario/training regression, smoke on every OS and blocker triage; no claim of published rating or store approval before actual approval.

Launch support retains previous signed builds/save fixtures, reproduces crashes privately with opt-in diagnostics, versions model/content/engine migrations and stages updates; a patch failure rolls back binary and compatible content without overwriting the only pre-migration save. A legally revoked performance definition requires a disclosed migration, not a quiet generic physics substitution. Publish release notes with known limitations and measured machine/build-specific results. If any gate misses, block its platform/tier or seek an explicit documented scope/gate decision; do not relabel targets as achieved results.
