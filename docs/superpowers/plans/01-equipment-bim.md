# Equipment, BIM and Vendor Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an upstream-respecting facility/equipment authoring pipeline, rights-gated realistic generic and optional licensed equipment packs, and an explicit game-construction-to-reviewed-design export path.

**Architecture:** Keep accepted OpenCEA/GrowBIM source artifacts immutable; compile disposable versioned semantic and separately cooked visual packs for a C++20 simulation/Unreal client. Extend missing *upstream* facility and MEP profiles rather than relaxing narrow placement reconciliation. Maintain typed neutral machine identity, source provenance and approval hashes, with detailed original generic equipment ensuring sponsor-independent progression.

**Tech Stack:** Python 3.12 offline authoring, existing OpenCEA program 0.1/design-envelope 0.2 JSON Schema 2020-12 and GrowBIM APIs, IFC4/IfcOpenShell 0.8.5, Blender 5.2.2 LTS/Bonsai 0.8.5 qualified narrow fixture, GLB, FlatBuffers/zstd, C++20/CMake and Unreal Engine 5.8.1 cooked assets; content-addressed restricted S3-compatible storage and Git LFS for approved redistributable source/content.

---

This is the binding implementation plan. **B01 has passed its upstream acceptance gate and is pinned as GrowBIM 0.2.0**; its execution record follows the checklist below. Commands in unchecked packages remain future acceptance contracts, not passing evidence. Use accepted upstream artifact APIs and validation, not duplicated OpenCEA schemas. Source policy: [BIM/asset pipeline](../../bim-and-asset-pipeline.md), [vendor program](../../vendor-program.md), [architecture](../../architecture.md) and [product specification](../../product-specification.md). B01/B05 upstream paths belong to GrowBIM/OpenCEA, not this repository; never modify the old Grownetics Sim study as a workaround. Unsupported future source profiles must still fail with precise diagnostics.
